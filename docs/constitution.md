## 1 · What this repo is

A ledger with views. Records are filed by **what they are** (provenance
class), immutable and dated; **what they're about** is computed as
derived views (tags → indexes, deps → threads). What-is-known is always
derivable from what happened — never the reverse.

## 2 · Content classes — there are exactly three

- **`exchanges/`** — the ledger. Immutable, dated, flat records of
  one-shot operator↔agent interactions. The only place agent content is
  born. Named `YYYY-MM-DD-<slug>.md`; schema in
  [exchange-schema.md](exchange-schema.md).
- **`docs/`** — the governing layer: doctrine, policy, purpose, intent,
  invariants, contracts, methods, tripwires. Defined by **ratification,
  not species of author**: operator-authored, or agent-originated and
  promoted by the operator. Authorship is carried by markers; an
  agent-originated doc carries a provenance link to its birth exchange.
- **`tools/`** — deterministic executable machinery. The directory marks
  role (plumbing); markers and provenance still mark authorship.

External sources enter as **footnotes** in the doc that cites them —
inclusion is always explicit, never general. Where preservation or depth
matters, the act of capturing the source is itself an exchange, and the
footnote also points at that record (link-rot mitigation).

## 3 · Vocabulary and views

- **`taxonomy/`** — the tag vocabulary as a directory tree. Vocabulary
  only, never content. Each leaf holds an `index.md` (a `#derived` view
  listing every record tagged with that path — links only, no copies;
  the leaf index is also what lets git track the tree). New tags may be
  proposed by the classifier; they exist once the operator commits them.
- **`threads/`** — `#derived` views materializing the deps graph: chains
  of exchanges by lineage. Regenerated by `tools/derive_threads.exs`.

Views answer "what else is about this" (indexes) and "what did this grow
out of" (threads). Both are projections of the ledger — regenerate, never
hand-edit.

## 4 · The nursery rule

All agent content is born in the ledger, as an exchange. Promotion out of
the ledger is the operator's ratifying act, and there are exactly two
promotion targets: **docs** (it governs) and **tools** (it runs).
Everything else stays in the ledger and is referenced by path.

## 5 · Authorship markers — every markdown file carries exactly one

- `#human-authored` — the operator wrote it.
- `#agent-authored` — a model wrote it; the file carries a provenance
  link to the exchange that produced it.
- `#derived` — a deterministic tool emitted it; regenerate, never edit.

Exchange files are composite: their sections carry the markers
(`## Prompt` `#human-authored`, `## Response` `#agent-authored`,
`## Side Effects` `#derived`).

## 6 · Mutability regimes — three, and only three

- **Immutable**: everything under `exchanges/` (sidecars included). The
  window closes at commit; before the commit, correcting a proposed field
  by hand is the audit working, not a violation.
- **Edit-in-place with dated supersession**: docs. Invariants in
  particular are append-and-supersede — superseded entries stay, dated;
  silent edits are forbidden.
- **Regenerated**: `#derived` views. Overwritten wholesale by their tool.

## 7 · Sidecars — evidence is kept, never deleted

Every capture persists the harness's raw JSON stream — including any
tool-use and tool-result records — as
`exchanges/envelopes/<same-basename>.json`, together with the shown-list
(what evidence the classifier was given). Verdicts about evidence never
destroy the evidence: a verdict without its evidence is unfalsifiable.
Any future retention policy is operator-ratified and executed by a
deterministic script — never an agent turn.

## 8 · Ratification and commits

No agent ever commits. Every commit is operator-made and gated by the
checks (`tools/check_all.exs`, wired via `tools/hooks/pre-commit`). The
operator's commit is the ratification event for everything in it —
including machine-proposed metadata the operator has read and accepted.

## 9 · No silent caps

Whenever machinery bounds coverage — a top-k, a truncation, a sample —
the bound is recorded where the result lands (sidecar or Side Effects).
"Found nothing" is meaningless unless what was searched is on record.

## 10 · Prerequisites

git · Elixir 1.14+ (1.18+ recommended) · jq 1.6+ (the tools' JSON
engine) · the `claude` CLI as inference backend #1
([backend-contract.md](backend-contract.md)). Elixir presence is a
declared repo prerequisite: agent and CI environments provision it; the
pre-commit shim fails loudly if it is missing rather than degrading.
